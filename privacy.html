Privacy Policy

Effective date: 8 November 2026 · Applies to: Hermes Agent (personal OAuth client)

1. Summary

Hermes Agent is a locally-installed, single-user application. It accesses Google API data belonging to its owner, on the owner's own computer, at the owner's instruction. No data is collected by the developer, sent to any server operated by the developer, or shared with any third party.

2. What data is accessed

3. How data is stored

Data is processed in memory on the owner's device. Persistent storage is limited to:

  • An OAuth refresh token, stored in a local file on the owner's computer (default ~/AppData/Local/hermes/google_token.json on Windows), readable only by the owner's operating-system user account.
  • Conversation history and any files the owner explicitly asks the application to create, stored locally on the same device.

No Google user data is written to any remote server, database, or cloud service.

4. Sharing and disclosure

Google user data is never sold, rented, transferred, or disclosed to third parties. It is not used for advertising, profiling, or training machine-learning models. It is not used to determine creditworthiness or for lending purposes.

The application does send selected content to the AI model provider that powers the assistant, solely to fulfil the owner's request (for example, summarising an email the owner asked about). That processing is governed by the model provider's own API terms, occurs only on the owner's explicit instruction, and is not controlled or retained by the developer of this application.

5. Google API Services User Data Policy

This application's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

6. Retention and deletion

The owner can revoke access at any time, which immediately invalidates the stored token:

  • From Google: myaccount.google.com/permissions
  • Locally: delete the token file named in section 3

Revocation destroys the application's ability to access the account. No copy of the data remains anywhere else, because no copy was ever made.

7. Security

Access uses OAuth 2.0 with the authorization-code flow and PKCE. Credentials are stored in files protected by operating-system user permissions. The application does not transmit credentials to any third party.

8. Children

This application is not directed at children and is not distributed to the public.
